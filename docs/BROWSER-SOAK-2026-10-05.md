## 已知限制

- 这是两轮约半小时生成负载，不是数天生产负载、真实认证书源、全部格式或最终本机非 root 镜像验收；不能用于证明随后 Chrome 诊断修正或其他新源码。
- 第一个到最后一个静默样本的内存仍增长约 47.648 / 69.551 MiB。没有触限或残留浏览器进程，不等于已证明不存在缓慢泄漏；未做长时稳态或 Java 堆存活对象分析。
- `CONTAINER_STATE.json` 在清理前采集，记录服务仍运行且没有 OOM/错误；不能把其中 `ExitCode=0` 当成结束状态。两个作业日志均有成功 `docker rm` 的精确自有容器 ID 输出，但没有另存删除后的 inspect。
- Node 20 actions 被 runner 强制以 Node 24 执行及 `punycode` 废弃警告仍存在；本轮没有修正这些警告。
- 没有使用真实 Cookie、网络书籍正文或本地书籍正文，没有向注册表推送镜像，也没有修改生产服务、数据、默认分支或正式 Release。

## 重复与回滚边界

工作流的离线持续测试模式需指定已成功的 native run、完整测试 revision、原生架构与 1,800 秒预算，下载身份守卫必须通过；不能将新构建冒充此前验收字节。使用当前 `browser-image.yml` 的手动入口重复时需两个新作业与新证据目录，不覆盖本轮冻结结果。

本轮只补验收记录，不做运行时补丁或存储迁移。源码和制品仍保持候选范围，未宣称完整项目交付。
