## 已核实的缺陷与修复边界

- **从恢复源码核实**：Java/Kotlin `User` / `formatUser` 没有每用户 `isAdmin` 字段。管理能力来自当前请求的管理密码验证，实际空间参数是 `userNS`，不是 `ns`；错误管理密码配合 `userNS=default` 会按旧逻辑回退本人空间。
- **从旧候选 JAR 运行核实**：管理密码错误返回 HTTP 200 / `isSuccess=false`；正确密码返回 HTTP 200 / `isSuccess=true` 和真实用户列表，仍无 `isAdmin`。旧 Vue 3 界面因此不显示系统配置按钮；14.035 秒失败记录、JAR 与截图保留在本机隔离目录。旧候选并非原始 3.2.14 JAR，不能把本次结果写成原 JAR 新差分。
- **实现**：删去后端不支持的用户角色编辑字段。内部 `isAdmin` 名称仅代表本标签页真实验证后的管理能力，不读写持久角色标志。账号退出/重新登录清除新管理凭据，刷新需再次真实验证；归属未知的旧 `reader_secure_key` 不读、不迁移、不删除。
- **空间传输**：axios 和原生 SSE / HTTP 听书源 / EPUB 请求使用 `userNS=default` 与 `X-Reader-Secure-Key`，不把管理密码拼入 URL，不覆盖调用方原有 `ns`。新增 `X-Reader-Namespace` 元数据确认实际空间；后端授权、错误密钥回退和 ReturnData 格式保留。流响应头发送后不重复写头。
- **失败关闭**：系统空间成功响应若缺少实际空间确认或回退到本人，前端不展示、不缓存该数据；全局管理接口不要求空间头。旧错误 `ns` 实现留下的 default 书架/章节缓存不读不迁不删，本人空间缓存保持原名。SSE 身份改变后不派发迟到事件。
