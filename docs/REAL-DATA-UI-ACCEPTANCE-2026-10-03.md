## 数据边界与已从恢复 JAR 实测的结果

用户明确授权后，使用只读 SCP 复制 `bookshelf.json`、`bookGroup.json`、`bookSource.json`、`bookSourceMap.json`、`replaceRule.json`，总计 5,954,546 字节。复制前后远端 SHA-256 一致，五份本地副本逐一匹配远端。数据仅位于 Git 忽略的 `build/` 隔离空间；生产用户文件、密钥、Reader 密码及登录令牌、Cookie 文件和电子书原文件未复制。公开记录只含汇总，不包含私有规则、请求凭据、书目或截图。

隔离服务使用单独生成的测试账号，监听已核验的 `127.0.0.1:18931`，停止自动书架/远程订阅更新、备份与用户清理。实际数据数量为 169 本、5 个分组、429 个书源及对应映射、27 条替换规则。候选登录后可见数量一致；书源页面显示 427 启用，替换规则页面显示 8 启用。

Chrome 控制通道仍返回不可用；随后使用用户已授权的 Codex 内部浏览器，实际完成：

- 错误密码显示中文错误，直接重新输入正确的隔离账号密码后进入书架；不勾选“记住我”，刷新后仍能读取同一书架。
- 429 个真实书源加载、中文筛选与返回书架；27 条真实替换规则页面可访问。

这些取样不是所有文本编码、429 个书源或完整生产用户权限的等价证明。界面截图及详细业务数据仅留本地忽略目录，不上传 GitHub。此次技能驱动的可见流程验收发现了单靠原有烟测未覆盖的刷新回退。

## 已定位并修复：显式章节入口刷新回退

修复前，目录入口为 `?chapter=0`，点击下一章已加载第二章正文，但 URL 仍为旧入口，刷新重新选择第一章。当前源码初始化把有效 `chapter` 查询参数置于服务端及本机已存进度之前；这个优先级解释了可复现结果，不是对原始 Vue 2 JAR 行为的推断。

提交 `21484980984ed9e1a78be1ce38b69d530d8dd8fb` 在当前章节改变时同步**已有的**显式章节参数，采用 router replace 保留其他查询参数和 fragment，不增加翻章历史；无显式章节的普通续读仍保留原进度恢复路径。该本机 Vue 3 恢复 JAR 已成功重建，SHA-256：`F315DFE881BC18186505622FCA0333E7C7D4DFC1B535A3DBDE5A53012FB31701`。

本机 136 项 Node 测试、Vue 类型检查、Vite 生产构建和 Java 浏览器测试类编译通过。针对上述实际复现，扩展原阅读旅程为：目录入读 → 下一章 → 刷新保持 → 上一章 → 刷新保持，同时检查无关 query/fragment 不丢失，仍验证 TXT/EPUB 导出。
