# 异步结果进入真实 Reader 书源解析链

日期：2026-10-06。上一增量 `0664dc7b` 的两份真实默认引擎各 15 项已通过，但那不自动证明 Promise 经 `searchBook`／规则解析后可用。本文记录新增的整镜像业务验收，不把本机 double 当成实际浏览器。

## 当前修改

扩展原有 `scripts/smoke-local-webview.py`，保留原来的四次用户 Cookie、两次历史同步输入格式及四账号并发测试，另加三个实际 Reader 请求：

1. GET：服务器初始 HTML 只有空容器，300 毫秒后才插入原始生成书名。书源 `webJs` 返回 Promise，有限等待 DOM 后改名、创建生成 Cookie、发一个标记 POST，完成后返回 HTML；Reader 必须经真实规则解析得到准确书名、作者和绝对书籍 URL。
2. POST：相同延迟样本，通过 Reader 保留 `q=async`、`X-Fixture: async` 与前一请求创建的 Cookie。脚本删除 Cookie，发一个标记 POST并返回最终 HTML。目标请求和脚本标记都必须恰好一次，不把重放当恢复。
3. 同一用户的后续搜索：恢复原生成书源，下一请求必须没有异步 Cookie。其他新账号的并发也必须不继承它，不能用陌生用户的空 Cookie 冒充原用户已撤销。

初始 HTML 不包含验收书名 `WebView异步书`，因此静态页面、未执行脚本或把 Promise 转成 `{}` 都不能通过。只使用生成书名／作者、自己的回环 HTTP 夹具和新建账号，没读取真实 Cookie 或本地正文。

## 独立报告门禁

新增 `scripts/verify-reader-async-smoke.py`，严格要求两个顺序明确的 GET／POST 观察、HTTP 200／布尔成功／空错误、解析字段、原请求形状、脚本标记一次以及同一用户下一次 Cookie 清理。数字／布尔不互相强制转换，失败不输出原始响应、Cookie 或异常正文，文件限额 64 KiB。

完整镜像、两个原生生产者、两个重载 runner 与共用发布导入器都必须执行该守卫。静态发布链另测三种“删掉门禁”的错误，防止门禁只写在文档里。Native 工作流补上共用夹具的路径触发，后续只改夹具也会触发真正原生验收。

CLI 只允许隔离 smoke 使用的 `127.0.0.1:18890/18891`；拒绝用户 Reader `18931`、生产域名、userinfo／查询参数／其他回环端点，必须在创建账号或启动夹具之前失败。测试 fixture 的私网允许只用于生成回环站点，不改产品默认安全策略。
