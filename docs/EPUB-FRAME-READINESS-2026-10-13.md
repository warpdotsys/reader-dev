# 原版 EPUB 的目标文档就绪验收

## 实际证据，而非已定位根因

使用未修改的准确托管 7d JAR，原始 JAR 在空隔离存储生成账号，再通过真实登录、导入和阅读界面测试新生成三章书。八个模式/导航/刷新步骤完成，旧正文采样在 `aria-busy=true` 时取样；已知章节标识、CSS 状态及严格正文比较仍一致。本轮没有复现大书正文比较失败，不能把“采样过早”认定为其根因。

第二轮加载与正式测试完全相同的只读判据，在实际 Firefox 再次完成这些生成步骤。两轮均为 2 CPU、2 GiB、256 进程、零交换，保留 15 秒 Worker 总期限。只读 DOM 观察器的测试状态与固定数值已单列，未修改 Reader 状态、请求、CSS、srcdoc、滚动或动画，也未导入个人浏览器会话。

这两轮的 `readerEightScenesAccepted` 明确为 false：生成书的采样诊断不能冒充获准大书或完整镜像交付验收。

## 正式测试加强项

共享判据 `browser-poc/src/test/resources/epub-frame-readiness.js` 要求：iframe 忙碌属性明确为 false；当前文档完成、字体加载完成；当前 DOM 与规范化 srcdoc 相同。旧文档即使已有文字，或 URL/srcdoc 属性已变化，也不能提前通过。

`RawEpubReadiness` 接入完整镜像 EPUB 初读、切章和刷新，以及既有本地原版/锚点/滚动恢复测试；继承原测试期限，不改变产品的字体等待、Worker 超时或资源预算。七项生成回归测试覆盖旧文档、忙碌/缺失状态、字体、空输入、异常及接线；本机全前端 360 项零失败，独立 browser-poc 测试源码编译成功。

可重复编译：在项目根目录、JDK 11 下运行 `gradlew.bat -p browser-poc compileTestJava --max-workers=2 --no-daemon --offline`。完整镜像与 Vue 测试仍须在 GitHub 托管 runner 对新提交独立执行，不能沿用 e31 的旧绿灯。

## 大书反例仍存在

AO 同原 Jar、单一获准 EPUB、原资源限制及全部八项要求，仅强化原版模式的就绪等待并增加私有章节标题比较。完成文本 805、文本 806、文本刷新和 HTML 806 后，首次原版排版在 Worker 解压阶段超时，iframe 未出现。就绪判据和刷新分类均未到达；仍不能区分此前正文变化原因。

本轮 96.001 秒，内存峰值 1,622,540,288 字节；没有 OOM。实例停止、PID 为零、独立 runtime 空后，仅逐一清理三份只读副本 37,824,508 字节，原件和来源保留。生成两轮各三份副本 19,611 字节也已清理。没有递归删除或修改生产。

启动前检查曾无输出拒绝，Reader 未启动；具体原因未确认。清理完成后独立确认单位 inactive/PID 0、系统无 D 状态，再通过带固定步骤跟踪的启动检查。不是因为观察超时而重启测试或 WSL。

证据：[生成章节两轮及共享判据](evidence/epub-generated-readiness-2026-10-13.json)、[获准大书尚未到达新判据](evidence/epub-authorized-readiness-unreached-2026-10-13.json)。

## 缺口、回退及下一项

大型 EPUB 的首次/刷新解压超时、严格正文比较和 iframe 可见性不稳定仍未解决。当前不发布、不合并、不部署。后续须装载准确托管完整镜像并核验，而不是继续把旧 401d 缓存运行时加一个新 JAR 等同最新镜像。

本次只加强测试，不改后端、ZIP 算法或正式前端。回退时移除 `RawEpubReadiness` 与两处测试接线及新增判据/回归测试即可，保留反例记录和原来的产品源码；不得恢复成仅凭大量文字就宣称目标章节正确的验收报告。
