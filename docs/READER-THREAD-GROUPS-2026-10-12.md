## 为什么需要这次诊断

旧授权单书 H/I 失败记录中，Java 曾为 69/70 个线程，浏览器为 162/165 个线程；PID 首次触限发生在刷新 text 的阶段，早于切 raw。它说明合计资源压力存在，尚不能证明 JVM 核数误识别、解压慢或某个线程池就是唯一原因。

此前独立 JVM 探针已实际见到 2 个 CPU。本轮进一步运行真正 Reader，用 `/proc/<自有 Java PID>/task/*/comm` 对线程归类，不用独立小程序的线程数替代应用。它是 Linux 截短线程名的类别计数，不是完整 Java 栈、ThreadMXBean、CPU 时间或锁等待分析；未知类别保留为 other。
