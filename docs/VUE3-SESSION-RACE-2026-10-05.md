更新日期：2026-10-05。源码候选；不是正式发布、生产验收或真实起点登录证明。

## 已实际复现的缺陷

只使用新建的本机隔离 Reader（`127.0.0.1:18945`）、新 Chrome 上下文及随机生成账号。用户 Reader `18931/PID 61244` 未动，没有真实账号、Cookie、真实书籍正文或生产写入。

在同一 SPA 文档中注册甲账号，暂扣甲的真实 `getBookshelf` 请求；点击退出、真实注册乙账号，乙的登录 HTTP 200 / `isSuccess=true`，直接访问乙的书架接口也成功。随后为甲的在途请求返回生成 HTTP 401，旧 Vue 3 全局拦截器清掉了乙账号的 token。不是“服务端拒绝乙登录”，也不是刷新导致旧请求被中止。

基线 JAR SHA-256 为 `c8b30b2d8f75d08865ebbeaf81a9cfe84cb38b993147a7a7dd4bcc60370baed8`。`baseline-c` 实际 1 项、1 失败、0 跳过/错误，6.124 秒；失败明确为旧账号的 HTTP 401 删除新账号 token，XML SHA-256 `bdf6f08ca804b982e67dd77ef0515bf69734261f51c60c1e5ce93cbe99a10f6e`。截图已目视确认当前导航显示未登录；截图处于路由动画过渡，不作为最终跳转完成证据。

## 源码修复

- 每次 axios 请求发送前捕获 token、账号、实际命名空间及只存在内存的会话代数。快照不持久化、不新增 URL 参数或请求头，也不记录凭据。
- 退出、重新登录及配置层切换更新代数；即使同账号同 token 的 ABA 变化，也不能把旧响应认作新会话。
- 响应进入拦截器后先检查所属会话，再决定返回业务数据、清除登录、跳转或弹全局错误。旧成功响应也拒绝，避免旧调用方晚到保存旧账号数据；旧响应以固定、不含账号/token 的 `READER_STALE_SESSION` 错误结束，不伪造成功。
- 当前会话确实收到 HTTP 401、HTTP 200 / `NEED_LOGIN` 或“请登录”业务错误时，仍按 legacy 行为退出并回登录表单。
- 匿名用户本就没有会话可过期，匿名认证错误不会更新代数或干扰并行的真实登录请求。
- 原生 fetch 的管理员探测也捕获/校验会话。更新管理员标记不再调用 `setSession(..., true)`，从而不把标签页登录变成“记住我”、不重置用户选择的配置层。实际空间没变时角色元数据刷新不取消并行书架请求；default 空间被撤销时旧请求失效。
- 退出时同时清除内存中的管理员状态。后端的 token、登录/API 契约、storage 格式和账号数量上限未改变。

## 必跑界面回归

`Vue3PreviewSessionRaceTest` 用真实后端注册/登录、真实界面退出/重新登录，不用手写 token 或注入 Pinia store。三种生成失效响应分别覆盖：

1. 旧甲请求晚到，乙登录仍保持，乙书架可见，不弹甲的全局错误。
2. 同账号新登录之后，旧成功书架不写入当前页面或离线书架。
3. 同账号再次登录之后，旧失效响应不能清除新会话。
4. 当前会话失效必须清 token、显示真实登录表单，原账号重试能回到书架。

页面之间只走 SPA 控件，不整页导航掩盖在途请求。测试输出只包含三种模式和布尔验收状态，不包含账号/token。GitHub Vue 工作流新增必跑/零跳过 XML 门槛和生成截图。
