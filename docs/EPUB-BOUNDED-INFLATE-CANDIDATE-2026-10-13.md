# EPUB 有界输出解码候选：尚未接受发布

## 已成功重建的源码改动

保留 fflate 的 ZIP 中央目录与本地条目分帧、路径规范化、重复路径拒绝及原有全部预算。DEFLATE 使用固定 `pako 2.1.0` 流式解码，每次输出最多 64 KiB；声明较小时仅保留“声明字节数 + 1”的输出容量，以便立即发现低报。直接核对实际字节并填入已有独占目的缓冲，不聚合第二份完整资源；截断、结束后的多余字节、压缩量不一致及无效预算均拒绝。

这是可读 TypeScript，不是 JAR 字节码热补丁；Java/Kotlin 后端、登录和数据格式未改。新依赖及类型定义固定版本，原锁文件 162 项既有依赖记录保持不变。适配器还读取固定版本的 `ended` 与 `strm.avail_in`；未来升级必须重新验证 EOF、尾随输入和分块结束协议，不能只更新版本号。实现依据：[固定版本解码源码](https://github.com/nodeca/pako/blob/2.1.0/lib/inflate.js)。

本机全前端 366 项零失败、零跳过；新增六项覆盖输出上限、完整字节、未知大小条目的结束交接、损坏/截断/尾随输入、压缩量和低报拒绝。既有 32 MiB 恶意样本低报 16 字节的 ZIP 回归现在断言仅产生 17 字节便中止。类型检查和 Vite 构建另验；新的托管构建不能借用 d313 的旧绿灯。

## 已知问题与发布门槛

- 大书原版排版硬刷新仍失败；候选不是完整修复，不合并、不发版、不部署。
- 最新完整镜像本机、剩余原 JAR/远程 WebView 三方、实站认证和长期稳定仍未完成。
- 本轮生产依赖审计识别五个 high 条目：`axios`、`vue`、`@vue/server-renderer`、`nanoid`、`source-map-js`；新增 `pako` 无报告条目。审计严重性不等于证明这些路径都可在当前浏览器制品利用；仍须补齐升级与可达性评估，不能写成“依赖全部安全”。

仓库生产 Compose 将 storage/logs 挂载到磁盘，而 AP/AQ 诊断把生成工作目录放在 tmpfs。下一项结合有界解码候选与独立生成磁盘目录核验；旧算法的磁盘单因素反例仍保留，不声称磁盘是唯一原因，也不放宽资源或期限。后续实际结果和托管制品须另记录。

当前最新本机源码候选 B 已重新构建并检查防御分支在真实 Worker 资源中：JAR `529b19193291490b87b023e8a77abdd6177cb3ff7090daee7e3d5d195d9742b5`，Worker `17c47eaf29cd3684b6dd8326205cba435d70344e66deb059bb585285a47f138a`；1,373 个非 Vue 文件仍与托管基线逐字节相同。AR 使用全新私有 ext4 生成目录和这份准确候选，保留原资源门槛与全部八场景，结果尚待核验。没有将 AP/AQ 初始构建冒称最新源码构建。

## 重复构建与回滚

在 `web-vue3` 执行 `npm ci`、`npm test`、`npm run build`，随后项目根目录 JDK 11 下执行 `gradlew.bat -PreaderWebUi=vue3 bootJar --max-workers=2 --no-daemon`。本机离线阶段把输出定向到独立 `build/bounded-epub-inflate-20261013-*`，不覆盖原 JAR 或已有默认产物；正式托管仍须两个 clean 构建的完整字节对照。

回滚只还原本轮的 archive 解码接线、适配器/测试及两个新锁定依赖，然后重建前端和 JAR；不能改动原始 JAR、用户数据、旧工程或已有未提交报告。保留所有反例与对照产物，原版 Vue 2 回退仍可用。
