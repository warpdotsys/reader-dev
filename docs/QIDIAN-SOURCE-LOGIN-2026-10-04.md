## 实际修复：不将已保存凭据误报为已登录

修复前，Vue 3 用 `reader_src_login_{url}=1` 这一不含用户命名空间的本地标记显示“已登录”。服务端已经撤销 Cookie 或用户换账号后，该标记仍可能存在；保存任意 Cookie 也被标为登录成功，并回显其前 20 字符。

新增隔离 Chrome 回归在未修复的组件上实际失败：`An obsolete local marker is not server authentication expected:<0> but was:<1>`。原 XML 保留在 `build/source-cookie-ui-20261004-a/baseline-failure.xml`，SHA-256 `d982dc68cf6900b6f2c4efa5665db00bad4f62b3c4c407ef65785c1a0fdbc2a1`。

修复内容：

- 只使用当前用户服务端 `getBookSourceCookie` 的存在状态；不读、不删除旧的无用户本地标记，不覆盖用户浏览器数据。
- 清晰区分“Cookie 已保存（未验证）”与目标站实际认证通过；不将保存 API 的成功响应当作第三方登录成功。
- 摘要仅保留 Cookie 名称与 `***`；不回显凭据前缀、认证头或未知敏感字段。关闭弹窗、换身份、卸载组件时清空输入。
- 读取失败或过时响应不能恢复旧状态；用户 token / default 配置身份变化时立即失效旧状态，并重新读取服务端。
- 撤销同域凭据后移除对应状态；管理列表不再用本地标记补出“幽灵已登录”书源。
