# 起点书源与凭据状态验收

## 已核实的边界

- 用户选择起点中文网作为真实登录态测试对象，尚未提供起点账号、密码或 Cookie。本轮没有复制第三方登录凭据、修改生产服务或读取其他本地书籍正文。
- 已授权的业务快照内存在两份起点配置，不据此推断有效性：移动版 `m.qidian.com` 启用 Cookie Jar、搜索未使用 WebView；桌面版 `www.qidian.com` 搜索使用 WebView、登录字段是网页 URL，Cookie Jar 标记为 false。两份配置均未提供 `loginCheckJs`，不能由 Cookie 存在证明登录有效。
- 已实际用内部浏览器打开 `https://www.qidian.com/` 并点击首页登录入口，看到扫码、账号登录页面。Chrome 的交互式工具连接不可用；本机安装的 Chrome 可以用于下面的隔离自动回归，两者不是同一结论。没有填入第三方账号、完成验证码或接受登录协议。
- **从源码核实**：当前 `SourceLoginController` 只执行书源提供的 `@js:` / `<js>` 登录规则；普通网页返回手动 Cookie 指引，验证码接口也未提供可交互会话。因此尚未宣称 Reader 内起点扫码登录可用。

## 实际修复：不将已保存凭据误报为已登录

修复前，Vue 3 用 `reader_src_login_{url}=1` 这一不含用户命名空间的本地标记显示“已登录”。服务端已经撤销 Cookie 或用户换账号后，该标记仍可能存在；保存任意 Cookie 也被标为登录成功，并回显其前 20 字符。

新增隔离 Chrome 回归在未修复的组件上实际失败：`An obsolete local marker is not server authentication expected:<0> but was:<1>`。原 XML 保留在 `build/source-cookie-ui-20261004-a/baseline-failure.xml`，SHA-256 `d982dc68cf6900b6f2c4efa5665db00bad4f62b3c4c407ef65785c1a0fdbc2a1`。

修复内容：

- 只使用当前用户服务端 `getBookSourceCookie` 的存在状态；不读、不删除旧的无用户本地标记，不覆盖用户浏览器数据。
- 清晰区分“Cookie 已保存（未验证）”与目标站实际认证通过；不将保存 API 的成功响应当作第三方登录成功。
- 摘要仅保留 Cookie 名称与 `***`；不回显凭据前缀、认证头或未知敏感字段。关闭弹窗、换身份、卸载组件时清空输入。
- 读取失败或过时响应不能恢复旧状态；用户 token / default 配置身份变化时立即失效旧状态，并重新读取服务端。
- 撤销同域凭据后移除对应状态；管理列表不再用本地标记补出“幽灵已登录”书源。

测试只使用新建的生成账号、`.example` 书源和生成 Cookie，后端为隔离候选 JAR，端口 18938；Vite 使用当前源文件、端口 18939；两者仅监听 127.0.0.1。用户端口 18931 / PID 61244 未停止或改动。

- 同一条 `Vue3PreviewSourceCookieTest` 修复后通过：1 项、0 跳过/失败/错误。覆盖旧标记忽略、保存后的脱敏/未验证提示、刷新、服务端实际撤销、同域共享，以及通过界面真实退出/登录切换账号后的隔离。
- 初次测试直接更换 query token 却保留前一个账号的 session cookie，因 legacy 后端优先 session 而失败；没有修改后端兼容策略，改为真正的界面退出/登录后重测。中间失败 XML 保留为 `artificial-session-mismatch.xml`，不隐去失败记录。

## 已知问题与后续门槛

- 起点真实账号、Cookie 有效性、已授权章节访问，以及原 JAR / 历史远程引擎 / 内置 Camoufox 的同条件三方对照仍未完成。
- 交互式扫码/验证码会话尚未实现，手动 Cookie 入口不是这个功能的替代验收。不得自动完成验证码、绕过收费权限，或把网站正常登录成功当作 Reader 登录成功。
- 若测试需要把起点登录凭据转入本机隔离 Reader，须先明确授权目标与用途；不得发送到聊天、GitHub、公开制品或生产服务。原 JAR 仍只能在验证过的仅回环 Linux 网络隔离环境运行。
- 本轮不创建正式版本标签、不推 registry、不部署。回滚仍按候选及正式部署文档执行，保留 Vue 2 回退界面和原 JAR。
