# Reader Pro v6.1.1-preview.1

临时候选，供隔离环境评估，不推荐直接升级生产。本版本用于保存第二阶段已实现的源码和发版改造；长期验收任务按用户要求暂停，不表示项目已全部完成。正式稳定版仍为 v6.1.0。

Git 标签使用 `v6.1.1-preview.1`，应用、CLI 及前端内部版本统一为 `6.1.1`。最终身份必须同时核对 `PREVIEW.json` 的 tag、revision 和 SHA-256，不能仅看界面版本号。候选通道不标记 Latest、不覆盖旧标签、不访问生产服务器。

## 主要变更

- 实现独立 OPDS Basic 鉴权、账号关联、Atom 目录和本人书架的本地 TXT/EPUB/PDF 下载，修正前端目录地址。
- 许可证中心增加可配置 SMTP、验证码有效期、错误次数、限流及单次申领；前端增加发送、领取与显式导入步骤。
- 修复 Reader 转发试用申领结果时将嵌套 JSON 包装为 `data.map` 的问题；管理密码只用于本次显式导入请求。
- 增加候选身份、完整备份事务和自启的实验性工具及生成数据测试，但尚未开放为完成交付的维护流程。
- 重组 GitHub 托管 CI，增加 Windows PowerShell 生成测试、许可证成品与双 clean 门槛，以及独立的预发布准备通道。

## 已知问题

1. **许可证真实界面闭环未完成复测。** 已复现领取响应结构错误并修复、重建；暂停时尚未用修复后的 JAR 重新完成领取和导入。不要把服务端协议测试当成此界面问题已经验收。
2. **OPDS 尚未完成完整应用验收。** Linux 生成 TXT 下载及跨用户、符号链接拒绝已测试；EPUB/PDF 下载、重启持久化、慢客户端断连与真实设置界面仍待验证。Windows 缺少安全目录句柄时下载会失败关闭。
3. **完整备份恢复未接通候选生命周期。** `full-backup.py` 的正式执行仍主动拒绝，防止备份期间并发启动或在半恢复状态下启动。旧维护脚本绑定 v6.1.0，不能用于本候选。
4. **可选自启没有真实注册或登录后验收。** 生成测试使用假的调度器适配器，不修改系统任务，不能据此承诺开机即用。
5. **新候选的四小时运行、新版本全套界面及准确镜像本机验收尚未完成。** 有限测试不保证永久无泄漏或所有书源兼容。
6. **生产状态和公网投递未验证。** 本次不连接生产服务器、不接入私人 Chrome、起点登录态或私人正文，也不使用生产 SMTP 或密钥。

## 验证范围

暂停前的开发快照完成了前端 427 项测试、许可证服务 15 项测试，以及 Reader 的 2 项转发响应和 5 项 OPDS 回归。Linux 独立 OPDS 契约使用已有非 root 用户和生成 TXT；这些结果不是当前候选最终镜像的证明。

候选流水线必须重新执行源码检查、前端和 JVM 测试、许可证 fat JAR 冒烟、双 clean 字节比较、35 项真实浏览器契约、Vue 3 界面场景，以及 AMD64/ARM64 镜像构建、重载和导入验证。失败时不生成候选总包或发布草稿。实际完成情况以本候选 SHA 对应的 Actions 运行及制品回执为准。

所有网页操作均由助手执行；18961 旧演示标签页也是助手打开，用户明确没有操作，不构成用户验收。Windows 自启测试和许可证 SMTP 测试均只使用生成数据。

## 升级与回滚

1. 先停止待升级实例，并离线保存完整数据目录、账号配置、许可证数据库和密钥，以及当前镜像身份。不得只备份一个用户 namespace。
2. 校验候选包的 `SHA256SUMS`；核对 `PREVIEW.json` 的源码 SHA 和 Actions 链接。保留稳定版镜像，不覆盖旧标签。
3. 在新目录用生成数据或另行批准的数据副本试运行，使用不同端口。不得让两个实例同时写同一数据目录。
4. 发现问题时停止候选，保留故障副本；恢复稳定版镜像和升级前匹配的数据备份。不能只换回旧 JAR 并假定新版本写过的数据一定向后兼容。

本候选不自动迁移或部署生产。上述步骤是隔离评估与回滚要求，不表示尚未接通的维护工具已可代替人工操作。
