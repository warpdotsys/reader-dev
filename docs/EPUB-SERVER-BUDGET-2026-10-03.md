# EPUB 服务端预算与失败导入保护

日期：2026-10-03。Java/Kotlin 恢复工程的增量修复；不是正式 Release、生产替换或整个项目完成。旧 Vue2 资源和原 JAR 保留，没有语言重写、字节码热补丁或空实现。

## 已成功重建：可达入口与明确限额

`importBookPreview` 在覆盖同名用户预览资产之前，验证 EPUB 目录、实际展开大小和 CRC。错误继续使用 HTTP 200 的失败 `ReturnData`，`errorMsg` 以“EPUB 文件校验失败：”开头；`data` 为 null 时沿用原 Gson 的字段省略行为，不擅自添加空数组或成功结果。

`EpubReader.readEpubLazy` 在旧 OPF/NCX 解析器之前校验实际压缩条目，避免大小/CRC 错误被旧异常处理转成空目录。懒加载单项读取检查实际大小和 CRC，不按攻击者声明的大小预分配数组；入口 ZipFile 与后续资源流均关闭。非懒加载资源另有 64 MiB 总预算。

| EPUB 项目 | 服务端上限 |
| --- | --- |
| 压缩文件 | 256 MiB |
| 声明及实际展开总量 | 1 GiB |
| 单项二进制 | 32 MiB |
| 单项 XML/OPF/NCX/XHTML/HTML/CSS/SVG | 16 MiB |
| 条目 | 10000 |
| 中央目录索引（分配 ZipFile 前） | 16 MiB |
| 一次实际读取的协作时间预算 | 30 秒 |

这些是编译期常量，不是已经提供的管理设置。时间检查发生在每次本地流读取之前，不能中断阻塞的系统调用。字节预算不是 JVM/浏览器总 RSS、图片解码像素或 XML 解析对象的内存保证。客户端原版排版仍使用[更小的独立预算](EPUB-RESOURCE-BUDGET-2026-10-03.md)。

共用的 `File.unzip` 覆盖备份/CBZ 路径时，采用更宽的通用 ZIP 预算：压缩 2 GiB、展开 4 GiB、单项 1 GiB、100000 条目，同样限制中央目录为 16 MiB。解包前检查全部路径，拒绝普通/百分号编码越根、协议路径、重复别名及文件/目录冲突；已知符号链接祖先拒绝，不改写原条目名或正文。

## 已成功重建：缓存事务与用户编辑

EPUB direct/legacy 解包先完成随机同级暂存目录的实际大小和 CRC 校验，再安装缓存；失败不提前删除旧缓存。程序自己标记的旧缓存可在安装成功后清理，清理不跟随符号链接。

未经标记的旧 legacy 缓存视为用户数据：普通读取不自动重建、不加标记、不移动，原有编辑保留；主动强制刷新先校验新缓存，再把旧目录保留为同级 `.previous-<UUID>`，不删除其中的用户文件。需要人工恢复时，应停该测试/服务的相关读取，保留当前缓存，将相应旧目录恢复到原路径，确认内容后再处理新缓存，不能批量删除 `.previous-*`。

## 有效失败基线与本机验收

四个小型基线在旧恢复源码上确实失败，0 跳过：普通/编码 `..` ZIP 被旧解包接受；128 KiB 生成资源的中央目录大小低报、CRC 伪报被旧懒加载读取接受。不是原 JAR 的同类坏文件测试，没有制造真实大型 ZIP 炸弹、压缩用户正文或预分配巨量内存。

修复后增加正常格式测试：小型 ZIP64、带注释 ZIP、中文名称、未压缩条目、旧 OPF 字节编码；另验证独立大小/条目预算、流中未知大小、总实际字节预算、文件/目录冲突、完整/异常中央目录，以及旧缓存保留和失败回滚。全量本机 Java 测试为 109 项，89 项执行通过，20 项因未提供外部 renderer 环境而跳过（Camoufox 11、旧 local renderer 9），不是 109 项全部通过。

新浏览器旅程用随机账号和七种小于 8 KiB 的坏 EPUB，经真实上传控件检查 HTTP/ReturnData、中文可见错误、合法同名预览原始字节不变；随后重新上传合法书、入架和阅读生成中文正文。一项 JUnit 包含七个失败分支，不记作七项独立 JUnit。登录、六本生成书完整阅读与备份还原另行回归。

## 尚未验证与已知限制

- 字节与 CRC 校验不等于完整 EPUB/XML schema 校验、图片像素预算、实体展开保护、所有 ZIP 方言或所有书籍兼容。故意拒绝超限/损坏文件是与旧版的明确行为差异。
- XML 中 container/OPF 引用的边界、Windows 所有 reparse/junction 情形、并发缓存替换与恶意同 UID 的 TOCTOU 仍需独立审计；不能声称全部路径与资源攻击已解决。
- 通用 ZIP 解包不是完整事务：路径预检失败不会开始写入，但晚发生的 CRC 错误可能留有部分文件。EPUB 专用缓存事务不能冒充所有备份路径的保证。
- 非标记 legacy 缓存保留用户编辑的策略可能每次读取重新扫描源 ZIP；308 ms 是单次磁盘测量，不是长期/并发性能保证。
- 当前托管门禁、真实需登录书源的三方差分、稳定版双架构发布/生产切换分别记录，不以本机测试、旧构建或可选 job 跳过代替完成。

## 可重复构建与回滚

JDK 11、Node 24、仓库锁文件与 Gradle Wrapper，在工程根目录执行：

```sh
npm ci --prefix web-vue3 && npm run build --prefix web-vue3 && PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 ./gradlew -PreaderWebUi=vue3 test bootJar --no-daemon --max-workers=2
```

本机使用独立 bootJar 输出目录，保留原始 JAR、旧候选、现有工程及用户未提交 reports；不迁移 storage/data 格式。产品回滚保留旧完整镜像和配置、原存储快照，沿用部署文档，不用 Git reset 或覆盖用户工作树。机器可读事实见[本机证据](evidence/epub-server-budget-local-2026-10-03.json)。
