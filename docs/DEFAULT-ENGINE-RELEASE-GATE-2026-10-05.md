# 默认浏览器发版门禁

更新：2026-10-05。此增量只改测试/工作流/证据留存，不修改已经托管复验的 `755bb7d9` worker 或存储逻辑；没有执行正式发版、标签、registry 登录或生产部署。

## 已验证的缺口

`26255c0` 的 Browser 工作流 37296514243 实际默认导航失败，而 Native 工作流 37296514255 成功。旧正式发布虽等待完整 Vue 旅程与原生镜像/重载/导入，却没有等待这一组更细的默认引擎契约。独立 Browser 工作流红灯不能自动阻止所有直接标签发版路径；不能只口头说“失败不发版”。

## 本次改动

将真实 Camoufox 13 项契约放在 Native 的共享 JAR **上传制品之前**，因此两个原生镜像、重新载入、publisher 导入及正式 registry 发布均通过既有依赖等待该作业成功。仍使用 GitHub 托管 Ubuntu 24.04，不加自托管 runner、宿主安装要求或外置 WebView 服务。

该作业固定 Python 3.10 与现有完整 SHA action，按生产锁与 `--require-hashes` 安装 Python 依赖，并校验固定 Camoufox 二进制；实际执行目标类后用共同的严格校验器检查精确 13 个唯一契约、零失败/错误/跳过、suite 与 case class、非伪造零汇总。最后逐字节核对 JAR 内 worker 与受测源码，再复核 JAR 散列。运行时安装/Gradle/报告/字节核对任一失败都不能上传共享发布 JAR；不加 `continue-on-error`、跳过条件或吞掉错误。

Browser 集成改用同一报告校验器，避免两套断言漂移。失败默认引擎 XML 使用 `always()` 留存；普通 Java CI 也新增所有 JUnit XML 留存，Native 先保留完整 JVM 报告再跑目标浏览器类，避免后一次 Gradle 覆盖早期报告。报告缺失为失败，不上传 JAR、HTML、真实凭据或私人正文作为诊断。

## 本机验证与尚未验证

- 发布校验共 54 项、0 失败/跳过，新增 7 项结构负向覆盖遗漏实际执行/报告/包内 worker 核对、未锁输入、两套校验器漂移、允许失败和悄悄跳过。
- Python 共 106 项、105 执行/1 环境跳过、0 失败；新增 9 项 XML 守卫使用**生成报告**，不能当作真实浏览器成功。
- 共同校验器实际接受 `755bb7d9` 的真实 13 项 XML，拒绝已经冻结的 13 项全跳过、1 项真实导航失败及旧 12 项通过报告；只输出安全的计数/报告 SHA，不回显失败内容。
- 三个修改工作流 actionlint 通过，未运行 shellcheck/pyflakes。工作流的执行次序仍需此增量自己的托管运行；此前 `755bb7d9` 的 57 项实际浏览器/XML、22 份镜像 JSON 不能用于宣称新发版依赖已经执行成功。

新契约增加时必须同步维护校验器名单与负向测试，不能用自动计数或允许未知用例绕过缺失。结构检查并非完整 YAML 语义证明，实际托管作业和发布依赖仍是必要证据。真实起点精确搜索/认证三方、无限真实导航与当前源码持续测试、完整产品/生产验收仍待完成。

回滚：在独立干净工作树撤回本工作流/守卫增量，不改变 `755bb7d9` 运行时。回滚会重新打开默认导航失败不一定阻止标签发布的缺口，必须保留为已知风险。禁止 reset/checkout 覆盖用户脏文件。
