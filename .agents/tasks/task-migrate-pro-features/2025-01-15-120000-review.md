# Pro feature migration: Vue components, backend route aliases, and simple-web source reconstruction

This change adds six Vue components (FileManager, HttpTTS, License, ActiveLicense, BookConfig, RemoteBookSourceSub) to the web frontend, registers path-based route aliases in the Kotlin backend (`/reader3/file/*`, `/reader3/httpTTS/*`, `/reader3/book/saveBookConfig`, `/reader3/user/downloadBackupFile`, `/reader3/book/tts`, `/reader3/textToSpeech`), and reverse-engineers the minified simple-web JavaScript/CSS/HTML into a readable `simple-web-src/` directory. The backend also gains several new controller methods (TTS synthesis, book content caching, book config save, license validation endpoint) and refactors BookmarkController/ReplaceRuleController into a generic CURD interface.

**Watch for:** The `getCommand` utility function in VertExt.kt executes arbitrary OS commands with no input sanitization or caller restriction — if any route eventually passes user input to it, it becomes a remote code execution vector (confirmed: function exists, no route currently calls it, but it's public API). The `decryptData` function uses plain Base64 decode, not actual cryptographic decryption, meaning license data is trivially readable by anyone with filesystem access (confirmed). The `ttsByApi` method in BookController performs server-side requests to arbitrary user-supplied URLs (SSRF risk, confirmed). The `ActiveLicense.vue` component hardcodes a default license key (`Pvkp7tMQJpi4kWBE`) in its `showForm` method (confirmed).

## High-level view

The Vue frontend gains a file manager with upload/download/delete/parse-books capabilities, an HttpTTS source editor, a license key generator/manager, a book PDF-width configuration dialog, and a remote book-source subscription manager. All components follow existing project patterns and are wired into Index.vue via event bus listeners.

The backend route aliases duplicate existing handler registrations under `/reader3/file/*` and `/reader3/httpTTS/*` path patterns that the Pro compiled frontend expects. New controller methods (`textToSpeech`, `saveBookConfig`, `saveBookContent`, `cacheBookOnServer`) add real functionality beyond aliasing.

The simple-web-src reconstruction is ~5,700 lines of vanilla JavaScript, CSS, and HTML organized into logical modules. It is not wired into any build pipeline — it exists solely as readable reference source alongside the minified production assets.

The CURD interface refactor replaces boilerplate CRUD logic in BookmarkController and ReplaceRuleController with a generic trait, reducing each from ~230 lines to ~60 lines.

<summary>Issues (7)</summary>

1. **`getCommand` enables arbitrary command execution** (confirmed) — The public function in VertExt.kt takes a list of shell commands and runs them via `ProcessBuilder` with no sanitization. No route calls it today, but it's importable by any controller. Either delete it or restrict access with an explicit admin-only gate.
2. **`ttsByApi` is an SSRF vector** (confirmed) — `BookController.ttsByApi` calls `webClient.getAbs(finalUrl)` where `finalUrl` is derived from user-controlled HttpTTS `url` field. An attacker who can save an HttpTTS source can make the server fetch internal network resources. Add URL validation (allowlist schemes, reject private IP ranges).
3. **Hardcoded license key in ActiveLicense.vue** (confirmed) — `showForm()` pre-populates a config object containing `key: "Pvkp7tMQJpi4kWBE"`. This exposes a default key in the source bundle that ships to all clients.
4. **`decryptData` is Base64-only, not encryption** (confirmed) — The naming implies cryptographic protection but the implementation is `Base64.getDecoder().decode(encrypted)`. License data is plaintext-equivalent. Either rename to reflect reality or implement actual decryption.
5. **`cacheBookOnServer` has no concurrency bound or timeout** (confirmed) — Iterates all chapters sequentially per book with no limit on total duration. For large books this holds server resources indefinitely. The frontend sets `timeout: 300000` but the server-side coroutine has no cancellation.
6. **`checkLicense` scheduled job always sets valid=true** (confirmed) — The 6-hourly job catches exceptions but still calls `setLicenseValid(true)` unconditionally in the try block. In community mode this is intentional, but the code structure is misleading if license enforcement is ever enabled.
7. **`saveBookContent` writes to filesystem without size limit** (confirmed) — Accepts arbitrary `content` string and writes directly to disk via `chapterFile.writeText(content)`. No maximum content size is enforced, enabling disk exhaustion by an authenticated user.

## Command execution utility and SSRF surface

`VertExt.kt` adds `getCommand(commands: List<String>, workDir: String, timeout: String)` which splits each command string on spaces and passes the result to `ProcessBuilder`. The function is public and unrestricted. No HTTP route currently delegates to it, but its presence in the utility layer means any future feature could accidentally expose it. The naive space-splitting also means commands with quoted arguments will break silently rather than failing loudly.

Separately, `BookController.ttsByApi` takes a URL from the user's HttpTTS configuration and issues a GET request from the server:

```kotlin
val finalUrl = url
    .replace("{{text}}", encodedText)
    .replace("{{speakText}}", encodedText)
    ...
webClient.getAbs(finalUrl).timeout(30000).send { ... }
```

Any authenticated user who can create an HttpTTS entry can point `url` at `http://169.254.169.254/latest/meta-data/` or internal services. The 30-second timeout limits damage but doesn't prevent information disclosure.

## License system posture

The license module takes an intentional "community mode" approach where `isLicenseValid` always returns `true`. However, the surrounding code creates a false sense of security:

- `decryptData` is named as if it decrypts but simply Base64-decodes. If an attacker obtains the stored license string, they can read all fields.
- `ActiveLicense.vue` hardcodes `key: "Pvkp7tMQJpi4kWBE"` as a default in the generate-license form. This key appears in every compiled frontend bundle.
- The scheduled `checkLicense` job runs every 6 hours but the try-block calls `setLicenseValid(true)` before any validation logic could fail it.

If the license system is ever activated, these patterns become vulnerabilities.

## TTS synthesis resource management

The `textToSpeech` dispatcher in BookController routes to one of three backends: Edge TTS (via a Java WebSocket library), an API-based approach (arbitrary URL with text substitution), or a fallback to `texttospeech.cn`. The Edge path creates a fresh `TTSService` per request — each instantiation builds an `OkHttpClient` and opens a WebSocket. Under concurrent load this will exhaust file descriptors.

The `ttsByTextToSpeechCn` method calls an external Chinese TTS service (`https://texttospeech.cn/api/tts`) with no circuit breaker. If the service is unreachable, requests hang for 30 seconds before timing out.

## Content writing without size bounds

`saveBookContent` accepts `bookUrl`, `chapterIndex`, and `content` from the request body and writes `content` to `${cacheDir}/${chapterIndex}.txt` with no size check. A user with a valid session could POST megabytes of content per chapter index, filling disk. Authentication is present but no rate limiting or quota exists.

`cacheBookOnServer` iterates all chapters of one or more books sequentially with no concurrency bound. For a 500-chapter book over a slow source, this coroutine runs for minutes or hours with no cancellation mechanism. The frontend's 300-second timeout closes the HTTP connection but the server-side coroutine continues running.

## simple-web source architecture

The reconstructed `simple-web-src/` mixes two reactivity paradigms: a `Watcher` class (observable values with `onChange` callbacks) used in the reader page, and a `createSignal`/`createEffect` signals pattern used in search/rss pages. This inconsistency is inherited from the original minified code and accurately reflects the production behavior, but makes the source harder to maintain than a unified approach would.

## Route alias attack surface

The `textToSpeech` route is registered at both `/reader3/textToSpeech` and `/reader3/book/tts`, each with both GET and POST handlers — four registration points for a single controller method. Combined with the SSRF concern in `ttsByApi`, this widens the surface an attacker can probe. GET handlers for TTS also mean the endpoint is trivially cacheable/linkable, though the auth check prevents anonymous access.
