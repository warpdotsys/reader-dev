## 已修复的差异

首轮差分为 10/12：在 Windows 上，原始 JAR 的文件列表路径使用系统分隔符（如 `\notes\差分.txt`），恢复版统一成了 `/notes/差分.txt`。依据黑盒结果，将 `FileController.list` 的路径拼接改回 `File.separator + relativeTo(baseDir).path`，重建后 12/12 一致。

扩展测试后，multipart 上传响应和目录解析预览也出现同类路径差异，且其它字段/字节一致。分别修复 `FileController.upload` 与 `FileController.parse` 的返回路径后，17/17 一致。在 Linux 上系统分隔符仍为 `/`，因此这些修复不改变线上 Linux 路径形式。没有把未测试的接口按相似源码批量改写。
